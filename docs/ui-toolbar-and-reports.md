## Что было сломано и почему

### 1. Развёрнутый API устарел (главная причина)

`https://itwin.kz/map-api` отдаёт **7 маршрутов** (`/fragments`, `/line`, `/node`, `/run-sety-cmd`, `/russian-names*`). Все `/api/*` — журналы, диагностика, паспорта, отчёты — отвечают `404`. В коде их 120.

**Требуется деплой [tgid-server](https://github.com/argokz/tgid-server) на боевой сервер.** До этого перечисленные функции в production работать не будут независимо от правок фронтенда. Диагностика неисправностей теперь распознаёт 404 и прямо сообщает, что на сервере устаревшая версия API.

### 2. Ведомости Excel падали с 500 (исправлено)

`reports_generator.py` обращался к несуществующим объектам схемы:
- `nodes.name`, `nodes.type` — таких колонок нет (есть `nodename`, `nodetypeid`);
- таблица `networkarmatures` — не существует (реальная — `dampers`, 14 868 записей);
- `heatpipesections.diameter/yearpipe/pipetype` — нет (есть `diameterinternal`, `diametercondit`, `diameterexternal`, `wallthickness`);
- типы `bp`, `ns`, `pt` вообще не обрабатывались и попадали в сломанную ветку.

Теперь генератор берёт данные из тех же проверенных функций, что и журналы UI (`get_network_armatures`, `get_network_bypasses`, `get_installed_pumps`, `get_consumer_load_diagnostics`), а по трубопроводам делает запрос на реальных колонках. Все 5 ведомостей отдают `200` с данными; неизвестный тип — `400` вместо `500`. Добавлены заморозка шапки, автофильтр и ширина колонок. Список типов доступен через `GET /api/reports/excel-types`.

### 3. HTML-формы показывали пустые ячейки (исправлено)

Форма `f11_defect` читала несуществующие поля (`defect_type_name`, `severity_name`, `defect_date`, `status_name`) вместо реальных (`source_name`, `state_name`, `category_name`, `detected_at`). Формы переписаны на фактические имена полей, добавлены `f13_inspection` и `f14_pressure`, значения экранируются, есть явное «записей не найдено».

### 4. Паспорт участка падал с 500 (исправлено в коде, блокирован данными)

Три последовательные поломки в перенесённом из gid8 `passport_module`:
1. `ModuleNotFoundError: config` — модуль использует плоские импорты; каталог не был на `sys.path`;
2. `ModuleNotFoundError: hyphen` — PyHyphen нет в зависимостях, при этом функция переноса слов сразу возвращает исходную строку, а единственный её вызов закомментирован → импорт сделан опциональным;
3. `connect_pg` писался под pyodbc (ODBC-DSN + `add_output_converter`), а драйвер подменён на psycopg2 → переписан на нормальное psycopg2-подключение;
4. эндпоинт передавал формам объект соединения вместо параметров (`connect.connect(**c)`) и **не строил граф участка** — вместо списка размеченных труб уходил `mark_line=0`, что давало невалидный SQL `join (values 0) …`.

Теперь эндпоинт повторяет полный desktop-сценарий: титульный лист (`ms1`/`rs1`) → состав участка → `sort_graph.make_graph` → 15 форм.

**Блокер данных:** в текущей БД `nodes.belongMagistralSite` и `nodes.belongDistSite` равны `NULL` у всех 91 523 узлов, то есть ни один узел не привязан к участку. Поэтому паспорт физически не на чем построить — API отвечает `404` с объяснением причины вместо `500`. После заполнения привязки участков сценарий нужно принять на реальных данных.
